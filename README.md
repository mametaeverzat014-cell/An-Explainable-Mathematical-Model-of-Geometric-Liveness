---

Исследовательский прототип (только программный, без специального оборудования) для
**обнаружения атак предъявления** — Presentation Attack Detection, PAD.
Система получает короткое RGB-видео (2–3 с) и относит его к одному из классов:

| Класс | Что это |
|---|---|
| `live` | настоящий человек, снятый камерой напрямую |
| `print` | распечатанная фотография лица, предъявленная камере |
| `screen` | лицо, показанное с экрана телефона, планшета или ноутбука |

В математической модели и метриках `print` и `screen` объединяются в один класс `attack`
(бинарная задача), а тип атаки сохраняется в метаданных для анализа по подгруппам.

## 1. Что изучает проект

**Исследовательский вопрос.** Может ли интерпретируемая оценка, построенная на
нормированной *временнóй* геометрии лицевых точек, отличать подлинные видео лица от
плоских атак предъявления лучше, чем статический однокадровый 2D-базлайн, при
субъект-дизъюнктном протоколе оценки?

Идея: у настоящего лица есть рельеф — кончик носа вынесен вперёд относительно щёк.
При движении головы перед камерой это порождает **параллакс**: взаимное расположение
точек в кадре меняется не так, как у плоского объекта. Распечатка и экран — плоские,
поэтому их геометрия при движении меняется иначе. Проект измеряет это одним
объяснимым числом — **Parallax Liveness Score (PLS)**.

## 2. Что проект НЕ изучает и НЕ делает

Это важная часть научной честности работы. Проект **не**:

* не распознаёт личность и не сравнивает лицо с базой зарегистрированных лиц;
* не является промышленной биометрической системой и не заменяет Face ID;
* не гарантирует безопасность и не даёт универсальных гарантий защиты;
* не утверждает, что «3D невозможно подделать»;
* не обнаруживает маски, дипфейки, все устройства и все виды атак;
* не использует облачные сервисы и не отправляет никакие данные в сеть.

**О координате z.** MediaPipe возвращает **оценочную относительную псевдоглубину**
(*estimated relative pseudo-depth*, псевдо-3D-геометрия точек). Это **не** настоящая,
не физическая и не измеренная глубина, и это **не** данные 3D-камеры. Значение z
предсказывается нейросетью по одному RGB-кадру. Формулировка «реальная глубина»
в отношении этого проекта некорректна.

## 5. Как заполнить `metadata.csv`

Файл `data/metadata.csv` содержит по одной строке на каждое видео. Обязательный заголовок:

```
video_id,relative_path,subject_id,label,attack_type,device,lighting,notes
```

| Колонка | Значение |
|---|---|
| `video_id` | уникальный идентификатор видео, без пробелов |
| `relative_path` | путь **относительно** `data/raw/` |
| `subject_id` | псевдоним участника (**не настоящее имя!**) |
| `label` | `live` или `attack` |
| `attack_type` | `none`, `print`, `screen`, `replay`, `curved_print` |
| `device` | чем снимали / чем предъявляли атаку |
| `lighting` | условия освещения |
| `notes` | свободный комментарий |

Правила согласованности (проверяются автоматически):
`label=live` требует `attack_type=none`; `label=attack` требует конкретного типа атаки.

Пример заполненной строки:

```
s001_live_01,subject_001/live/live_01.mp4,subject_001,live,none,webcam_720p,office_daylight,поворот и кивок
s001_print_01,subject_001/print/print_01.mp4,subject_001,attack,print,webcam_720p,office_daylight,фото A4
```

Строки, начинающиеся с `#`, игнорируются — в шаблоне так оформлены примеры.

Если все записи лежат в одной папке, раскладывать вручную не нужно. Назовите
файлы по шаблону `<участник>_<тип>_<номер>` — например `s001_live_01.mov`,
`s001_screen_02.mov` — и выполните:

```bash
python scripts/import_videos.py --source ~/Desktop/видео --dry-run   # посмотреть план
python scripts/import_videos.py --source ~/Desktop/видео             # разложить
```

Тип записи распознаётся и по-русски (`лайв`, `экран`, `печать`). Если вся папка
принадлежит одному участнику, его можно задать флагом: `--subject s001`.

Файлы по умолчанию **копируются**, а не переносятся: записи участников
невосстановимы, и оригиналы должны остаться на месте, пока вы не убедитесь,

### 5.2. Автоматическая сборка таблицы

Заполнять таблицу вручную не обязательно. Если видео разложены по структуре
`data/raw/<участник>/<тип>/`, таблица собирается сама:

Остаётся дописать эти поля для новых записей.

## 8. Метрики: APCER, BPCER, ACER

Обозначим `live` = подлинное предъявление (bona fide), `attack` = атака.

* **APCER** (Attack Presentation Classification Error Rate) —
  доля **атак**, ошибочно принятых за живое лицо:

  `APCER = (число атак, классифицированных как live) / (общее число атак)`

  Это ошибка безопасности: злоумышленник прошёл.

* **BPCER** (Bona fide Presentation Classification Error Rate) —
  доля **подлинных** предъявлений, ошибочно отклонённых как атака:

  `BPCER = (число live, классифицированных как attack) / (общее число live)`

  Это ошибка удобства: настоящего человека не пустили.

* **ACER** (Average Classification Error Rate) — средняя ошибка:

  `ACER = (APCER + BPCER) / 2`

* **Accuracy** — доля верно классифицированных видео от всех видео.

Меньше — лучше для APCER, BPCER, ACER; больше — лучше для Accuracy и ROC-AUC.

Дополнительно поддерживается риск-ориентированный выбор порога:
`L(tau) = lambda_attack · APCER(tau) + lambda_live · BPCER(tau)`.
По умолчанию `lambda_attack = lambda_live = 1.0`; увеличение `lambda_attack`
в `configs/prototype.yaml` делает систему строже к атакам.

## 9. Математическая модель кратко

Для каждого кадра `t` берутся 6 точек: нос, левый и правый глаз, левая и правая щека,
подбородок (индексы MediaPipe заданы в `src/constants.py` и легко меняются).

```
d2D(a, b) = sqrt((x_a - x_b)^2 + (y_a - y_b)^2)
IOD(t)    = d2D(глаз_левый(t), глаз_правый(t))        # нормировка на размер лица

r1(t) = [z_нос(t) - (z_щека_л(t) + z_щека_п(t))/2] / [IOD(t) + eps]   # рельеф носа
r2(t) = d2D(нос(t), глаз_л(t)) / [d2D(нос(t), глаз_п(t)) + eps]        # лево-правая асимметрия
r3(t) = d2D(нос(t), подбородок(t)) / [d2D(щека_л(t), щека_п(t)) + eps] # верт./гориз. пропорция

G1 = Var_t[r1(t)],   G2 = Var_t[r2(t)],   G3 = Var_t[r3(t)]
```

Нормализация оценивается **только на обучающих участниках**:

```
Gk_norm = [Gk - mean_train(Gk)] / [std_train(Gk) + eps]
PLS     = (G1_norm + G2_norm + G3_norm) / 3
```

Правило: `live`, если `PLS >= tau`, иначе `attack`. Направление неравенства может быть
изменено на противоположное, но **только по обучающим данным** (`pls.direction: auto`),
никогда — по тестовому участнику.

Сравниваются три модели: **B0** — мажоритарный базлайн, **B1** — статический
однокадровый 2D-базлайн (StandardScaler + LogisticRegression по одному среднему кадру),
**M1** — предложенная временная модель PLS.

## 10. Субъект-дизъюнктная кросс-валидация (LOSO-CV)

Основной протокол — **Leave-One-Subject-Out**: по очереди каждый участник становится
тестовым, остальные — обучающими.

Зачем это нужно: если видео одного человека попадут одновременно в обучение и в тест,
модель может «узнать» индивидуальные особенности лица, а метрики окажутся завышенными.
Это называется **утечкой данных** (data leakage), и результат перестаёт отражать работу
системы на новом человеке.

Правила, которые соблюдает код:

1. все видео одного участника всегда в одном и том же тестовом фолде;
2. разбиение **никогда** не делается по кадрам;
3. видео одного участника не могут быть одновременно в train и test;
4. нормализация признаков оценивается только на обучающих участниках;
5. статический базлайн обучается только на обучающих участниках;
6. порог `tau` выбирается только по обучающим/валидационным участникам;
7. каждый тестовый участник оценивается ровно один раз;
8. предсказания и номера фолдов сохраняются, поэтому любая метрика воспроизводима.

Порог выбирается внутренним LOSO по обучающим участникам. Если обучающих участников
слишком мало (`pls.min_train_subjects_for_inner_val`), применяется фиксированное
задокументированное правило, а ограничение указывается в отчёте — **подбор порога по
тестовому участнику не выполняется никогда**.

  с согласия родителя или законного представителя.
* В `metadata.csv` используются **псевдонимы** (`subject_001`), а не настоящие имена.
* Публиковать исходные видео без явного отдельного согласия участников нельзя.
* Участник вправе в любой момент отозвать согласие; тогда его видео и производные
  файлы (`results/landmarks/*.csv`) удаляются.
* Проект **нельзя** использовать для тестирования чужих реальных систем контроля
  доступа. Все эксперименты проводятся только на собственных записях.
* Код не выполняет сетевых запросов и никуда не загружает видео.

Подробнее — в [`data_card.md`](data_card.md) и [`protocol.md`](protocol.md).

## 12. Устранение неполадок

**Сообщение «НЕТ ДАННЫХ ДЛЯ АНАЛИЗА».**
Видео не найдены. Проверьте, что файлы лежат в `data/raw/`, а пути в колонке
`relative_path` указаны **относительно** `data/raw/` (без префикса `data/raw/`).

**`Ошибка metadata.csv: ...`**
Проверьте заголовок (все 8 колонок), отсутствие дублей `video_id` и допустимые значения
`label` / `attack_type`. Для `live` обязательно `attack_type=none`.

**Строки пропускаются с предупреждением «файлы не найдены».**
Опечатка в `relative_path` или другое расширение файла. Поддерживаются
`.mp4`, `.mov`, `.avi`, `.mkv`, `.webm`, `.m4v`.

**`no_face_detected` в `landmark_quality_report.csv`.**
MediaPipe не нашёл лицо. Обычные причины: слишком тёмное или контровое освещение,
лицо слишком мелкое или обрезано, сильное размытие, слишком резкое движение.
Переснимите: лицо крупно в кадре, равномерный свет, плавное движение.

**`too_few_valid_frames` / `low_valid_ratio`.**
Лицо теряется на части кадров. Снимите видео длиннее (2–3 с), уменьшите скорость
движения или улучшите освещение. Пороги настраиваются в разделе `quality_control`
конфигурации.

**`degenerate_iod`.**
Лицо слишком мелкое в кадре — подойдите ближе к камере.

**`Could not find a version that satisfies the requirement mediapipe`.**
Обновите `pip` (`python -m pip install --upgrade pip`) и ставьте зависимости строго
через `pip install -r requirements.txt`: там прописан выбор ветки MediaPipe по версии
Python. Команда `pip install mediapipe==0.10.21` на Python 3.13+ действительно
не сработает — для этой ветки сборок нет.

**`Нужен локальный файл модели MediaPipe`.**
У вас Python 3.13+ и ветка MediaPipe 1.x. Выполните команду `curl` из раздела 3.2
**в каталоге проекта** и запустите пайплайн снова.

**`Could not open requirements file` / `can't open file 'scripts/run_pipeline.py'`.**
Команда запущена не из каталога проекта. Выполните `cd` в папку, где лежит
`requirements.txt`, и проверьте `pwd`.

**`zsh: command not found: #`.**
В интерактивном zsh символ `#` не считается комментарием. Не копируйте в терминал
строки-комментарии из инструкций — только сами команды.

**Прочие ошибки установки MediaPipe.**
Обновите `pip` (`python -m pip install --upgrade pip`).
Если установилась версия `mediapipe>=1.0`, выполните
`pip install "mediapipe>=0.10,<1.0"` либо укажите путь к локальному файлу модели
в переменной `FACE_LANDMARKER_TASK`.

**`OpenCV не смог открыть видео`.**
Неподдерживаемый кодек или повреждённый файл. Пересохраните видео в MP4 (H.264).

**`Для LOSO-CV нужно минимум 2 субъекта`.**
Добавьте записи второго участника: протокол по определению требует нескольких людей.

## 13. Научная честность

* Проект решает задачу **PAD**, а не распознавания личности.
* `z` MediaPipe — **оценочная относительная псевдоглубина**, не измеренная глубина.
* Результаты справедливы **только** для протестированных людей, устройств, условий
  съёмки и классов атак; на другие условия они не переносятся автоматически.
* Ни один результат не может быть представлен как универсальная гарантия безопасности.
* Малые выборки дают **разведочные** (exploratory), а не подтверждающие выводы.
* Итоговый вывод обязан сравнивать PLS с базлайном по **реальным субъект-дизъюнктным**
  результатам из `results/`, а не по ожиданиям.

## 13.1. Научная работа

Полный текст работы — [`report.md`](report.md). Сборка PDF одной командой
(внешние конвертеры не нужны, используется установленный браузер):

```bash
python scripts/build_report_pdf.py
```

Получаются `report.html` и `report.pdf`. Оба файла собираются заново из
`report.md`, поэтому в репозитории не хранятся.
